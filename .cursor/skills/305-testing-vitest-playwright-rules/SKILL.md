# 테스트 — Vitest + Playwright

## 피라미드 (TDS §27.1)

```
Static (tsc · lint · compliance)  →  Unit (Vitest)  →  Integration (Vitest)  →  E2E (Playwright)
```

## GWT 가 SSOT다

인수 조건은 태스크 명세(`tasks/step-*/TASK-XXX.md`)의 **Given/When/Then 문장**이다.
테스트 이름을 시나리오명과 그대로 일치시킨다 — 명세와 테스트가 따로 놀지 않게.

```ts
describe('TASK-204 별 원장', () => {
  it('시나리오 2: 동일 idempotencyKey 재요청 시 신규 행이 생성되지 않는다', async () => { ... })
})
```

## 구현↔검증 페어

`204↔301` · `212↔302` · `210↔303` 은 짝이다. **페어가 통과하기 전에 다음 태스크로 넘어가지 않는다.**

## 단위 테스트

- `services/` 의 순수 로직을 대상으로 한다. Next 런타임 없이 돌아야 한다.
- **경계값을 먼저 쓴다** — 잔액 0에서 차감, 정확히 14일 정체, 계획 금액과 동일한 결제.
- 별 원장: 동일 키 **5회 동시 호출 → 지급 1회**를 반드시 검증한다.
- 성장 나무: `학습 10회 + 실천 0회 → 승급 불가`, `13일 정체 미판정 / 14일 넛지`.
- 통과시키려고 단언을 약화시키지 않는다. **실패를 먼저 재현**한 뒤 고친다.

## 통합 테스트

- 실제 DB 트랜잭션 경계를 검증한다. 테스트 DB 를 격리하고 케이스마다 롤백한다.
- 소급 정산: 48h 지연 승인 시 **과거 Cycle 에 정상 귀속**되고 스냅샷이 보정되는지.

## E2E (Playwright)

- 보안 시나리오가 1순위다 — **미동의 아동 URL 직접 접근 차단 100%**. 클라이언트 리다이렉트가 아니라 서버 차단인지 확인한다.
- 전 여정: 계획 카드 → Sandbox 결제 → 대조 → AI 회고 → 별 지급.
- 외부 의존은 Mock Sandbox 로 고정한다. 실제 Gemini 호출에 의존하는 E2E 를 만들지 않는다 — 쿼터와 비결정성 때문에 반드시 깨진다.
- 시각 의존 테스트는 시스템 시각을 고정한다.

## 금지

- `it.skip` 을 남긴 채 커밋
- 스냅샷 테스트로 도메인 판정 로직 검증
- 테스트 안에서 프로덕션 DB 접근
