# 에러 진단 7단계

> **증상을 지우지 말고 원인을 찾는다.** 테스트를 통과시키려고 단언을 약화시키거나 `try/catch` 로 덮는 것은 수정이 아니다.

## 1. 재현
정확한 명령어와 입력을 기록한다. 재현되지 않으면 아직 고칠 단계가 아니다.

## 2. 원문 확보
에러 메시지·스택트레이스 **전문**을 읽는다. 요약하지 말고 첫 프레임부터 본다.
Prisma 는 에러 코드가 핵심이다 — `P2002`(unique 위반) · `P2003`(FK) · `P2025`(레코드 없음).

## 3. 경계 좁히기
`app` / `actions` / `services` / `lib` 중 어느 레이어인가.
DB 문제인가 로직 문제인가 — 실패한 쿼리를 직접 실행해 본다.

## 4. 가설 세우기
"왜 이런 값이 왔는가"를 문장으로 쓴다. 가설 없이 코드를 바꾸지 않는다.

## 5. 최소 검증
가설을 확인하는 **가장 작은** 실험을 한다 — 로그 한 줄, 단위 테스트 하나.
여러 곳을 동시에 바꾸지 않는다. 무엇이 고쳤는지 알 수 없게 된다.

## 6. 수정
근본 원인을 고친다. 같은 클래스의 버그가 다른 곳에도 있는지 확인한다.

## 7. 회귀 방지
**이 버그를 재현하는 테스트를 먼저 추가**하고, 그 테스트가 실패하는 것을 확인한 뒤 고친다.

## 이 프로젝트에서 자주 나오는 것

| 증상 | 먼저 볼 곳 |
|---|---|
| `P2002 idempotency_key` | 정상 동작일 수 있다 — 멱등 재요청은 기존 행을 반환해야 한다 (REG-005b) |
| 잔액과 원장 합계 불일치 | 트랜잭션·행 잠금 누락. `FOR UPDATE` 확인 |
| 커넥션 고갈 | `PrismaClient` 싱글톤 위반. `lib/prisma.ts` 확인 |
| Gemini 429 | 정상 분기다. Fallback 이 동작하는지 확인 (ADR-010) |
| 아동 화면 접근 가능 | `middleware.ts` 가드 범위에 새 라우트가 빠졌는지 (REG-001) |
| E2E 간헐 실패 | 시각 의존 또는 실제 외부 API 호출. Mock Sandbox 고정 확인 |
