## 2. 제품 한 줄 요약

만 8~9세 아동의 **금융 행동 실천을 기록하고 그 변화를 보호자에게 증거로 제시하는** 폐쇄형 선불카드 기반 금융교육 플랫폼.

- **선언 ①** — 자녀가 금융을 학습하고 **금융 행동을 실천하며 성장**한다 *(아이 · 실천 계층)*
- **선언 ②** — 얼마나 배웠는지가 아니라 **금융 행동이 어떻게 달라졌는지**를 한 눈에 보여준다 *(보호자 · 증거 계층)*

선언 ①이 선언 ②의 전제다. 북극성 KPI는 **WPA(주간 실천 인정 아동 비율)** 하나다.

## 3. SRS 문서 구성

SRS는 **사내 SRS 표준 양식(1~7장)** 을 그대로 따른다. 요구사항·인수 기준·검증 방식·착수 조건이 **전부 4장 안에** 있어, 개발·테스트·유지보수 사이클에서 **4장 하나만 보면 되도록** 구성했다.

| 장 | 내용 |
|:-:|---|
| 1 | 서론 — 목적 · **범위(In / Out / 제약)** · 정의 |
| 2 | 이해관계자 · 주 사용자 특성 |
| 3 | 시스템 맥락 및 인터페이스 |
| **4** | **구체적 요구사항** — 4.1 전제조건·스프린트 배분·릴리즈 게이트 / 4.2 기능 **18** / 4.3 비기능 **24** / 4.4 규제 **9** |
| 5 | 추적성 매트릭스 |
| 6 | 부록 — API · 데이터 모델 · 비즈니스 규칙 · DB 스키마 · 이벤트 명세 · 모니터링 SLA · **성과 지표** · **ADR 8건** · **가정·리스크** |
| 7 | 향후 개선 사항 |

**4장 요구사항표 한 행에 들어 있는 것**

| 컬럼 | 흡수한 내용 |
|---|---|
| **인수 기준** | Given/When/Then (`G`/`W`/`T`) + **예외·실패 케이스**(`E`) — 기능 요구사항당 **예외 2개 이상** |
| **검증 방식** | 테스트 종류 + 검증 실험 번호 + **판정 임계치** |
| **출처** | PRD 절 번호 + **ADR 번호**(왜 이렇게 정의됐는가 → 6.8) |

표준 양식에 대응 절이 없는 내용은 버리지 않고 **부록 6.5~6.9**에 참조 자료로 두었으며, 각 절에 ISO/IEC/IEEE 29148:2018 근거를 밝혔다 — §9.6.11(외부 인터페이스) · §9.6.18(시스템 속성) · §6.3.3.3·§6.6.3(성과 측정) · §5.2.8(Rationale · Risk) · §9.6.8(가정·의존성). 범위 제약은 §9.6.7, 착수 순서 배분은 §9.6.9를 따른다.

## 4. 저장소 관리 규칙

- **최종 산출물만 올린다.** 참고 문서(표준 원문 · 타 제품 SRS 예시)와 이전 판본은 저장소에 포함하지 않는다
- 두 문서는 **서로 참조**한다 — SRS 요구사항표의 「출처」 열이 PRD 절 번호를 가리킨다. 한쪽을 고치면 다른 쪽의 참조를 함께 확인한다
